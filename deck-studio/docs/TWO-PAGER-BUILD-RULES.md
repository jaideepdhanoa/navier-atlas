# Two-pager build and release rules

Canonical standalone toolkit: [`../two-pagers/partner-two-pager/`](../two-pagers/partner-two-pager/README.md).

1. Recover the current company source and existing partner research before recreating either. This PDF lane is separate from live Google Slides and Atlas proposal/economics builders.
2. Preserve the original; create a partner project. One authored content file must drive dark/light editions.
3. Page one explains the company and proof. Page two explains the partner-specific fit, each side's contribution, three practical workstreams and one bounded next ask.
4. Register factual claims, evidence class, as-of date and audience clearance. Keep measured/demonstrated/plan/model/proposal distinctions visible. Company-reported traction is not independent accounting verification.
5. Use exact approved images with provenance and maturity labels. Inspect full-resolution vessel geometry and actual image crops. Never replace a real photograph with a synthetic scene while retaining a photograph label.
6. Do not shrink type to disguise an overflowing page. Trim content, restructure or reduce decorative area. Keep headline/traction/ask legible in phone previews; do not claim dense body copy is readable without zoom.
7. Build exactly two Letter pages, embedded fonts, no clipped text/missing assets/footer collisions, identical dark/light copy and a clean configured disclosure scan.
8. Inspect actual PDF page renders in both themes and phone-size previews. Record the visual inspection against the PDF/render hashes; automatic geometry checks are not visual inspection.
9. Preserve source, assets, outputs, claim/source registers, backup and QA receipts in durable storage.
10. Public repository publication uses a reviewed allowlist. Keep private communications, confidential brief/config files, personal contact details and non-public deal/technical material at their approved access level. A forwardable confidential brief is not automatically a public asset.

Public research home: [`../../reference/partners/`](../../reference/partners/README.md). For a Slides deck, continue using the existing Deck Studio manifests/edit-plan workflow instead of a PDF/PPTX round trip.
