# Proposal Completeness Audit — Bolt TAM ladder + network-wide shallowness

**Date:** 2026-06-24 · **Source:** `navier-atlas` main · **Machine-readable:** `PROPOSAL-AUDIT.json`

## TL;DR
Two separate things are going on, and you've diagnosed the root correctly:

1. **The Bolt TAM ladder is *not* structurally broken — it's standardized** (the 5-rung
   SOM→SAM→TAM→platform contract, generated deterministically). What makes it *look* wrong is
   **the base it rests on**: of Bolt's "376 corridors mapped," only **35 are sourced/minted** and
   **341 are census (synthetic greenfield)**. So every rung above the floor is a transform of a
   mostly *un-minted* number, plus three cosmetic data bugs (below).
2. **The loop is half-finished network-wide.** Grok mints corridor geometry → hands back to Tasklet →
   Tasklet completes economics + narrative. **Both halves have stalled:** corridors largely un-minted
   (census / cluster-dots / "aspirational-no-built-route" journeys), and **36 of 58 proposal files have
   no growth ladder at all.** There has been no systematic mint→handback→complete cascade.

## Part A — The Bolt TAM ladder: why it looks broken

**It IS standardized.** Bolt carries the full 5-rung contract, identical in shape to Grab/Careem/FP:

| Rung | Basis | Bolt mid |
|---|---|---|
| SOM — floor | 35 sourced flagship corridors · 10% capture · today | **$1.54M** (displayed "$2M") |
| SOM — full network | whole mapped network (376) · 10% · today | $7.5M |
| SAM — matured | induced demand + default-operator capture | $33.9M |
| TAM — journey GMV | every cross-water journey, all merchants | $407M |
| Platform revenue | partner commission on GMV | $18M |

Generated by `finance/model/growth_frontend_block.py` from `agg-<partner>.json` + a census. **This is the
deterministic model→deck step → Grok's lane.** So yes — this is a "tell Grok to regenerate" fix, not a
hand-edit. The four reasons it reads as "wrong data / missing detail between steps":

1. **91% of the base is census, not sourced.** `sourced_corridors: 35`, `greenfield_corridors: 341`.
   The *only* difference between the floor rung and the full-network rung is "35 sourced" → "376 whole
   census." There are **no minted corridors in between**, so the jump $2M→$8M is a census haircut, not a
   built network. This is the corridor-minting gap showing up as a number.
2. **Floor rounding inflates the headline.** Mid is **$1.54M** but displays **"$2M"**, and the page
   headline repeats "floor $2M/yr." The floor looks bigger than it is and collides with the headline.
3. **Stale provenance pointer.** Bolt's `source_rollup` still names **`careem-aggregate.json`**
   (copy-paste leftover) even though the numbers are Bolt-specific. Erodes trust if anyone audits it.
4. **The census base (35/341) is shared across ~20 partners.** It's a *global* census, not
   partner/region-specific — which is why **adani-ports and reliance-industries have byte-identical
   ladders**, and **ola / rapido / uber-india sit within ~1%** of each other ($16.2M floor, ~$79M
   network, ~$357M SAM). Different partners should not share a TAM.

## Part C — Root cause: the mint → handback → complete loop stalled

The intended pipeline (per `grok-seal-handoff` + `partner-model-cascade`):

> **Grok mints corridor geometry** (BP minting, route binding) → **hands back to Tasklet** → **Tasklet
> completes economics (cascade → ladder) + narrative** → Grok reseals the deck/map.

The audit shows **both ends open:**
- **Grok side:** corridors not minted at scale — census stands in for sourced (35/341), 50+
  sub-proposals are cluster-dots, hundreds of journeys are aspirational-null.
- **Handback side:** no systematic return to Tasklet, so **36 files never got a ladder** and the un-minted
  corridors never got cascaded into real economics.

This is exactly your read: *"Grok has a lot of corridor minting to do and hasn't been doing it, and there
has been no handoff back to Tasklet to complete the proposals."* Confirmed by the data.

## What we need Grok to do (deterministic — Grok's lane)
1. **Mint the backlog of corridors** so census → sourced: prioritize the cluster-dots sub-proposals and
   the null-route journeys (start with the all-unbuilt ones: minor-hotels, grab-thailand, gojek, then
   the India ride-hail set). Bind real `route_id`s; 0 silent drops.
2. **Regenerate every TAM ladder** (`growth_frontend_block.py`) once corridors are minted, so the
   network/SAM rungs rest on sourced geometry, not a shared global census.
3. **Fix the data bugs:** (a) per-partner census/rollup so adani≠reliance and the India set
   differentiates; (b) Bolt's stale `careem-aggregate.json` rollup pointer; (c) floor-rounding so
   $1.54M doesn't display "$2M."
4. **Hand back to Tasklet** after each mint batch (the missing return leg).

  newly-minted route_ids (hospitality at $1M, commercial at $900K/$600K, per the locked tiers).

  beats confidently-wrong*).
- Refresh sheets + master tracker + `economics_url`; ship the economics sidecar.
